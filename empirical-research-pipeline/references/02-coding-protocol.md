# 编码协议与 codebook

## 先定分析单位

在 codebook 第一页写死：

- 一行代表什么：文档 / 受访者 / 案件 / 机构 / 问卷答卷 / 地区-年度。
- 多单位资料：整体编码，还是拆成多行？如果整体编码，个体差异会被平均掉，必须在局限中说明。
- 混合主体：单位与个人、家庭与成员、机构与分支机构是否合并。
- 关联资料：同一事件的多份文档、一审+二审、同一受访者的多次访谈，是保留全部，还是只保留最终版。

这些决定会改变所有 N，不能等到跑模型时再改。

## codebook 的每个变量必须包含

| 字段 | 说明 |
|---|---|
| 变量名 | 英文短名，如 `stage` |
| 中文标签 | 论文表格里的名称 |
| 定义 | 一句话说清“测什么” |
| 取值 | 0/1、1–5、连续值；每个值要有文字标签 |
| 判断规则 | 什么算命中，什么不算 |
| 证据位置 | 原文段落 / 访谈片段 / 表格字段 / 外部数据 |
| 正例 | 一句原文或一条记录 |
| 反例 | 一句容易误判的原文 |
| 缺失规则 | 未记载、无法判断、不适用分别怎么记 |
| 理论/测量 | 是文本直接编码，还是理论赋分 |

理论赋分的变量（如“制度环境评分”）不能写成“从资料中直接测得”。方法部分要说明：这是研究者依据外部标准/理论框架做的编码，只用于机制检验。

## 编码顺序

1. **先编码客观字段**：年份、地区、机构、编号、类型、来源。
2. **再编码事实字段**：行为/事件、处理方式、阶段、持续时间、金额/规模。
3. **再编码结果字段**：结果表述、程序性结果、金额、状态。
4. **最后编码控制变量**：个体/机构特征、程序性控制、其他解释变量。

先易后难，先把能自动校验的字段做干净，再处理需要解释的字段。

## 编码工作表的自动字段

`make_coding_sheet.py` 只做候选抽取，最终编码仍由 codebook 决定。它对任何文体的读法一致，不内置领域字段；法院、案号这类某类文书的字段写在项目自己的 `--extract` 剖面里（`references/09-field-extraction.md`）。

| 字段 | 规则 | 仍需人工做什么 |
|---|---|---|
| `rel_path` / `relpath` | 相对 `--root` 的路径，统一用 `/`，两列同值（契约键列） | 作为与 audit/dedupe/统计脚本对接的主键 |
| `source_type` | 文件扩展名/类型（pdf/docx/txt/html…） | 确认格式是否影响文本完整性 |
| `doc_type` | 恒为 `document`（文件种类，不是文体分类） | 文体/类别判断写进 codebook 或项目剖面，不由脚本猜 |
| `title` | 首个有效行（≥2 字符），无领域词表 | 核对标题是否被页眉/导航污染 |
| `year` | 文件名年份优先，其次正文；只认 1949–今年、且前后都不是数字的四位数 | 统一年份口径（发布/事件/裁判） |
| `*_src` | `year_src`/`doc_type_src` 记录取值来源 | 来源为 `fallback` 的字段重点复核 |
| `category_candidates` | 关键词词典命中的类别候选；文件名命中优先，其次正文命中 | 不要把正文引用的其他类别当主类别 |
| `signals` / `evidence` | 关键词命中的证据句，每词最多 3 句；输出契约格式证据串（见下节） | 按 codebook 判定，否定表述优先 |

领域字段（案号/法院/省份等）不在工作表里：要抽它们，读样本后把切段和字段写进项目剖面，用 `--extract` 产出 `dataset.csv`。包内 `profiles/` 只是字段形状示例，`--extract` 会直接拒绝它们。

所有排除（扩展名、格式、读取失败、0 字节、低于 `--min-chars`、`--audit`、`--dedupe-plan`）统一写入 `skipped_documents.csv`，列为 `rel_path,relpath,file,doc_type,chars,reason,detail,skip_stage,file_kind`；`skip_stage` 取机器可读枚举（`ext_filter/format/read/size/min_chars/audit/dedupe`）。同时写 `sample_flow.csv`（列 `stage,n,note`，`n` 单调不增：文件总数 → 有效文件 → 通过筛选 → 编码完成），漏斗可直接从产物重建。`--audit` 清单里没有任何 `valid` 行时，脚本先把每个文件写进 skipped，再以退出码 2 结束，不会假装“成功抽取 0 份”；确需 0 行输出时显式加 `--allow-empty`。

## 证据片段规则

每个编码值旁边保存一段原文，并带上它在正文中的位置。统一格式（契约）：

```text
<字段>=<片段>@<char_start>-<char_end>
```

多个证据用中文分号 `；` 连接。`<char_start>`/`<char_end>` 是片段在**原始正文**中的字符偏移（左闭右开）。片段超过 200 字时截断为前 199 字加 `…`，偏移仍指向完整片段，便于回原文核对。

```json
{
  "file": "example_interview_001.txt",
  "rel_path": "interview/example_interview_001.txt",
  "stage": 3,
  "evidence": {
    "stage": ["stage=示例：受访者表示相关款项已经支付@120-146"]
  }
}
```

上例为虚构占位文本，不对应任何真实资料；实际编码必须引用原文。

规则：

- 证据句必须来自**资料正文/访谈原文/结果字段**，不能来自研究者概括、他人转述或附件中的建议。
- 否定优先：同一句里“不支持/未发生/不予认定/驳回”先于“支持/发生”判定；每个命中都带 `negated` 与 `polarity`（positive/negative），并列命中时按否定记账。
- 一句话同时包含多个事实时，拆分到对应变量，不要整句复制到所有字段。
- 分句保留顿号/逗号边界（在 `、，,` 之后切分），避免把两个相反判断黏在同一句里。
- 找不到证据句：记 `NA` 或 `未记载`，不要记 0。0 表示“文本明确说没有”，不是“没找到”。
- 同一份资料由多段组成时，记录段落/页码/时间戳，便于回溯。
- `signals` 的 included/skipped 计数打印在 stdout（每词上限 3 句），用来核对证据是否被截断。

## 有序层级变量

以“处理阶段”为例：

| 值 | 标签 | 判断要点 |
|---:|---|---|
| 0 | 未识别处理事实 | 全文没有可核实的承诺、支付、实施、确认 |
| 1 | 仅请求或判令 | 只有请求、建议或决定责令，未见主体主动行为 |
| 2 | 承诺或协议 | 承诺书、协议、计划、意向 |
| 3 | 已支付或缴纳 | 已支付/缴纳相关款项，有凭证 |
| 4 | 实际实施 | 已实际履行相关行为 |
| 5 | 已确认或完成 | 有确认、完成或效果评估记录 |

编码规则：

- 按资料时点**可查证的最高阶段**编码。
- 支付与实施并存，按更高阶段；只有支付凭证，不能推定已实施。
- “责令履行”是要求，不是已履行；不能记 4/5。
- “承诺履行”但没有后续履行，记 2，不记 4。
- 同一事项有多个版本时，以最终版/最完整版为准，并在证据中注明版本。

## 二元变量的正负规则

以“是否出现某结果”为例：

- 正例：同一句/相邻分句把某事实与结果表述明确连接。
- 反例：只提到事实，没有连接结果；或结果只针对其他情节。
- 排除：他人建议、转述、附件中的方案，未被最终资料采纳。
- 否定：明确写“不予支持/不足以认定/不适用”。

二元变量必须有“0 的定义”，否则 0 会混入“没写”“写了但没连接”“写了否定”三种情况。

## 问卷/量表/结构化抽取

- 先做项目级变量字典：题号、题干、取值、反向题、缺失码。
- 多选/排序题拆成 0/1 或多列；量表总分先检查信度（α/ω）和维度。
- 开放式题项先主题编码，再转成计数/类别变量；不要直接把词频当主题。
- 表格数据的主键、单位、时间字段必须能回溯到原始文件或原始行。
- 合并多来源数据时，先定主键与去重规则，再合并；保留来源列。

## 导出到 SPSS 的导入语法

`csv_to_spss_syntax.py` 生成的 `.sps` 必须满足：

- **编码一致**：`--encoding` 默认 `utf-8-sig`，写文件的编码与 `/ENCODING` 声明一致（utf-8 → `UTF8`；gb18030/gbk → `GBK` 并以该编码写文件；big5 → `BIG5`）。不允许 UTF-8 字节配 `GBK` 声明。
- **数值列不因个别值降级**：千分位（`1,234`）与 NA 哨兵（`NA/N/A/null/None/-/—`）按数值/缺失处理；真出现非数值才退回字符串，并在 stderr 列明哪一列、首个非数值是什么。
- **缺失值**：每个数值变量写 `MISSING VALUES var (-99, -98, -97).`；若数据本身已出现这三个值，改用 `-999999/-999998/-999997` 并在 stderr 说明。
- **测量层次**：每个变量写 `VARIABLE LEVEL var (NOMINAL|ORDINAL|SCALE)`；字符串与二值列 NOMINAL，3–10 级整数列 ORDINAL，其余 SCALE。
- **值标签**：分类变量写 `VALUE LABELS`（占位：值→值，待 codebook 替换）；值标签按 SPSS 上限截到 120 字节以内。
- **分隔符**：`--delimiter` 省略时按表头自动嗅探 `, ; 制表符 |`；表头只解析出一列而数据行有多列时打印 WARN。
- 参差行计数并 WARN，不静默丢值；改名结果写 `renamed_map.csv`（`raw,spss_name,format,renamed`）。

## 信度检验

至少做一次：

用 `scripts/compute_kappa.py` 对齐两轮独立编码并计算一致率与 Cohen's κ。两轮各产出一份 `dataset.csv`（同一个项目剖面、同一批抽样材料）：模型初编码与之后的独立复读算两轮；有两名编码员更好。

```bash
python scripts/compute_kappa.py --a output/coding/r1/dataset.csv \
    --b output/coding/r2/dataset.csv \
    --a-evidence output/coding/r1/evidence.jsonl \
    --b-evidence output/coding/r2/evidence.jsonl \
    --out output/kappa
```

产出三件：`kappa_report.csv`（每变量 n/一致数/一致率/κ）、`disagreements.csv`（逐条分歧 + 双方证据行，裁决从这里开始）、`coding-sample.md`（抽样复核记录骨架）。脚本不判断谁对：分歧只列出来，裁决仍由人/模型做并记录理由。多轮编码目录放规范组子目录（`output/coding/r1`、`output/coding/r2`），**不得**建 `coding-r1` 这类一级目录——目录骨架闸门会判杂散。

空值与列不对齐的约定：单元格写 `（未编码）` 表示该变量在这份材料上没有编码（不算「无/0」，也不算缺失一致）；两轮都会跳过这种单元格。`rel_path`/`relpath`/`file`/`doc_id`/`id`/`name`/`filename` 只作对齐键，`*_src`、`doc_type`、`run_order` 是溯源列，这些列一律不进 κ。只有一轮编了的变量不会静默消失：stdout 和 `coding-sample.md` 会点名「仅 A 编了 / 仅 B 编了」。

1. 随机抽 10%–15% 资料（不少于 30 份；材料很少时写明实际份数，不要为了凑数重复计算）。
2. 两名编码员独立编码、同一人隔两周重编码、或模型初编码后独立复读，都算两轮。
3. κ < 0.6 的变量回到 codebook 修规则（compute_kappa 会在输出里点名）。
4. 分歧逐条裁决，记录裁决理由；codebook 升版本。
5. 在论文方法部分报告抽样比例、κ 和分歧处理方式。没有第二轮编码时报告抽样设计和“不是 κ”；分层重读不能写成 κ。

## 结构化抽样复核

抽样复核的样本不能自己挑：同一双手既抽样本又复核对，等于没复核。用 `scripts/sample_review.py` 把抽样变成可复现的协议：

```bash
python scripts/sample_review.py draw \
    --review output/coding/extraction_review.csv \
    --dataset output/coding/dataset.csv --strata doc_type \
    --seed 20261118 --rate 0.1 --min-per-stratum 2 \
    --out output/review
```

口径：

- **种子必填**：同一 review + 同一 dataset + 同一 seed 重跑得到逐字节相同的 `sample.csv`，「抽了哪些行」本身成为可核对的事实。换 seed 就换样本，别在复核发现问题后换 seed 重抽。
- **分层**：`--strata` 按 dataset.csv 的列（默认 `doc_type`）分层；`needs_review` 是强制第二维度——被标记过的行是风险池，永远单独成层，不被大池稀释。`--n` 固定总量时先给每层保底（按层规模封顶，保底装不下就拒绝），再按剩余容量比例分配（最大余额法）；`--rate` 按比例抽，`--min-per-stratum` 给每层保底。
- **锚定**：`sample.csv` 每行自带 `rel_path/field/span/raw`——复核者回原文核对，不凭印象。
- **裁决三值**：`verdict` 只能写 `保持` / `改判` / `无法核对`；改判必须给 `corrected_value`（引擎强制：改判行没有改正值按未完成处理，exit 2）。空着就是没复核完。

复核完跑 `tally`：

```bash
python scripts/sample_review.py tally \
    --sample output/review/sample.csv --fail-above 0.10
```

`tally.json` 按层统计保持/改判/无法核对，列出全部改判项（含改正值）。有一行没填 verdict 就 exit 2——半张样本不是完成态。`--fail-above` 是你声明的改判率上限，超了 exit 2：这不是失败，是引擎替你守住你自己定的线（改判率超标说明抽取规则要修，不是删掉超标行）。

## LLM 辅助编码的边界

LLM 可以：

- 抽取全文、标题、年份、编号、关键字段。
- 找出候选证据句。
- 按明确规则做初筛。
- 发现规则冲突和边界案例。

LLM 不可以：

- 在没有证据句的情况下直接给最终编码。
- 代替人工做理论赋分。
- 把“模型觉得像”写成“资料认定”。
- 在未抽检的情况下全量生成最终数据。

推荐流程：LLM 初筛 → 人工抽检 10% → 修正规则 → LLM 全量 → 人工复核高风险样本 → 冻结。
