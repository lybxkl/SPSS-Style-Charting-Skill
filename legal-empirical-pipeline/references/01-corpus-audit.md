# 语料审计与去重

## 目标

在编码前回答四个问题：

1. 文件夹里到底有多少份文书？
2. 有多少份能读出文字？
3. 有多少份是同一份文书的重复副本？
4. 每一份被排除的文件，原因是什么？

审计不是“数文件”，而是建立**文件级状态机**。每份文件最终只能落在以下一类：

| 状态 | 含义 | 是否进入样本 |
|---|---|---|
| `valid` | 可打开、有文字层、属于研究对象 | 是 |
| `out_of_scope` | 年份/类型/地区不符合纳入标准 | 否 |
| `metadata` | `._*`、`.DS_Store` 等系统文件 | 否 |
| `hidden` | 隐藏文件/隐藏目录中的文件 | 否，除非用户确认纳入 |
| `unsupported` | 扩展名不在 `--ext` 中（如无扩展名、`.docx`） | 否，转换或改用 `--ext` 后重审 |
| `quarantined` | 位于 `_duplicates` 等 `--skip-dir` 目录 | 否，已隔离的副本 |
| `zero_byte` | 0 字节 | 否 |
| `corrupt` | 打不开、文件损坏 | 否 |
| `encrypted` | 有密码/权限限制，未提供密码 | 否，除非能解密 |
| `image_only` | 只有扫描图、无文字层 | OCR 后可用，否则排除 |
| `textless` | 有页面但既无文字也无图片 | 否 |
| `duplicate` | 与另一份内容相同 | 只保留一份 |

## 先跑审计脚本

```bash
python scripts/audit_corpus.py \
  --root "语料目录" \
  --out-dir "output/audit" \
  --min-chars 100
```

`--ext` 支持 `pdf`、`txt`、`md`、`csv`；纯文本按字符数审计。其他扩展名（如 docx）会直接报错，避免把非 PDF 当 PDF 解析。Word/HTML 请先转为文本或 PDF。

加密文件在读取正文前就会被标记为 `encrypted`，不会混进 `corrupt`；`corpus_summary.json` 的 `by_top` / `by_year` 只统计唯一样本（`valid` 且不是副本），元数据、坏文件、隐藏文件、扩展名不符的文件、已隔离副本都不会虚增样本结构。审计会把所有文件都列进状态表：不匹配 `--ext` 的文件记为 `unsupported`，`_duplicates` 里的文件记为 `quarantined`，不会再静默漏计；`total_files` 应能与资源管理器逐项对账。

输出解释：

| 文件 | 关键列 |
|---|---|
| `corpus_audit.csv` | `relpath, bytes, pages, chars, images, encrypted, md5, error` |
| `corpus_duplicates.csv` | `group, md5, keeper, file, pages, chars` |
| `corpus_summary.json` | 总数、有效数、重复组、年份分布、错误分类 |
| `corpus_report.md` | 可直接放进项目日志的中文摘要 |

## 重复检测：三层

### 第一层：字节级（必须）

同一文件被下载两次，MD5 完全相同。这是最可靠、最应优先清理的重复。

```text
MD5 相同 → 同一内容 → 保留一份
```

保留规则（按优先级）：

1. 文件名含完整案号（如 `(20XX)X0000刑初XX号`）。
2. 文件名含年份且无 `副本`、`(1)`、`...` 等下载痕迹。
3. 路径更短、目录层级更浅。
4. 文本字符数更多（防止截断版本）。
5. 其余情况人工裁决。

### 第二层：案号级（强烈建议）

从正文提取案号，规范化后比较：

```text
(20XX)X0000刑初XX号
（20XX）X0000刑初XX号
20XXX0000刑初XX号
```

全角/半角括号、空格、`第`字、`号`字都可能不同。规范化后相同，但 MD5 不同，说明是同一案件的不同下载版本或不同排版，需要人工复核后去重。

### 第三层：标题级（辅助）

去掉这些噪声后再比较：

- 日期前缀：`2021.04`、`2021年4月`、`2021.4.12`
- 案号前缀：`[（20XX）X0000刑初XX号]`
- 下载后缀：`_YYYYMMDD下载`、`- 副本`、`(1)`、`(2)`、`...`
- 法院名称中的“原××县人民法院”
- 案由写法差异：`完整案由` vs `案由简称`

标题相同但正文不同，可能是同案不同被告人的文书，**不能**直接去重。

## 去重脚本

先出计划，不直接删：

```bash
python scripts/dedupe_corpus.py \
  --audit "output/audit/corpus_audit.csv" \
  --root "语料目录" \
  --out-dir "output/audit"
```

确认 `dedupe_plan.csv` 后，再执行移动：

```bash
python scripts/dedupe_corpus.py ... --apply
```

`--apply` 只把副本移动到 `语料目录/_duplicates/<原相对路径>`，不删除。这样即使误判，也能恢复。`--copy` 改为复制，适合先保留现场做复核；重复执行时会自动生成 `__dup2` 等后缀，不会覆盖。目标目录不是语料根目录时会直接报错。

## 常见坑

- **文件名不是身份。** 同一案件可以有多个文件名，同一文件名也可以对应不同案件。
- **`._*` 文件也会被 `find *.pdf` 数进去。** 它们通常 4 KB 左右，打不开，但不是 0 字节。
- **0 字节文件在资源管理器里可能显示为 0 KB，但仍占一个文件名。** 必须单独列。
- **路径超长/尾随点。** Windows 下 `os.walk` 能读到，但资源管理器可能打不开；以 Python 审计结果为准。
- **“重复”不等于“应删”。** 有些同案文书是不同被告人的分别裁判，正文不同，不能去重。
- **去重后要重跑所有模型。** 不能只改正文的 N，表格、图、OR、CI 都要重算。
- **把 `._*` 的年份算进年份分布。** 汇总只应统计 `valid` 文书；否则元数据文件名里的年份会虚增年度样本。

## 审计报告必须写的三句话

1. 原始文件数、有效文书数、唯一样本数、分析样本数分别是多少。
2. 重复副本有多少组、多少份，分布在哪些地区/年份。
3. 被排除的文件分别是什么原因，是否有清单可查。
