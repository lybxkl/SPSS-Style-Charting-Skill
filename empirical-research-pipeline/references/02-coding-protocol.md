# 编码协议与 codebook

## 先定分析单位

在 codebook 第一页写死：

- 一行代表什么：文档 / 受访者 / 案件 / 机构 / 问卷答卷 / 地区-年度。
- 多单位资料：整体编码，还是拆成多行？如果整体编码，个体差异会被平均掉，必须在局限中说明。
- 混合主体：单位与个人、家庭与成员、机构与分支机构是否合并。
- 关联资料：同一事件的多份文档、一审+二审、同一受访者的多次访谈，是保留全部，还是只保留最终版。

这些决定会改变所有 N，不能等到跑模型时再改。

## codebook 的每个变量必须包含

| 字段 | 说明 |
|---|---|
| 变量名 | 英文短名，如 `stage` |
| 中文标签 | 论文表格里的名称 |
| 定义 | 一句话说清“测什么” |
| 取值 | 0/1、1–5、连续值；每个值要有文字标签 |
| 判断规则 | 什么算命中，什么不算 |
| 证据位置 | 原文段落 / 访谈片段 / 表格字段 / 外部数据 |
| 正例 | 一句原文或一条记录 |
| 反例 | 一句容易误判的原文 |
| 缺失规则 | 未记载、无法判断、不适用分别怎么记 |
| 理论/测量 | 是文本直接编码，还是理论赋分 |

理论赋分的变量（如“制度环境评分”）不能写成“从资料中直接测得”。方法部分要说明：这是研究者依据外部标准/理论框架做的编码，只用于机制检验。

## 编码顺序

1. **先编码客观字段**：年份、地区、机构、编号、类型、来源。
2. **再编码事实字段**：行为/事件、处理方式、阶段、持续时间、金额/规模。
3. **再编码结果字段**：结果表述、程序性结果、金额、状态。
4. **最后编码控制变量**：个体/机构特征、程序性控制、其他解释变量。

先易后难，先把能自动校验的字段做干净，再处理需要解释的字段。

## 编码工作表的自动字段

`make_coding_sheet.py` 只做候选抽取，最终编码仍由 codebook 决定。默认 `--profile generic`，适合访谈、新闻、政策、报告、网页、会议记录等任意文本资料；`--profile legal` 才额外抽取法院、案号、省份、案由。

| 字段 | 规则 | 仍需人工做什么 |
|---|---|---|
| `source_type` | 文件扩展名/类型（pdf/docx/txt/html…） | 确认格式是否影响文本完整性 |
| `doc_type` | generic: 文件类型；legal: 判决/裁定/调解/决定/其他 | legal profile 下核对文书类型是否符合纳入范围 |
| `title` | 正文首个非空行，或文件名 | 核对标题是否被页眉/导航污染 |
| `year` | 文件名年份优先，其次正文前 500 字 | 统一年份口径（发布/事件/裁判） |
| `case_no` | 仅 legal profile：文件名案号优先，其次“本院/我院/本案”附近案号 | 核对是否误取引用案例 |
| `court` | 仅 legal profile：文件名法院优先，其次正文前 2000 字 | 核对法院层级 |
| `province` | 仅 legal profile：路径省份目录或法院名前的省/市/自治区 | 统一地区口径；无省份留空并注明 |
| `category_candidates` | 关键词词典命中的类别/案由候选；文件名优先，正文兜底 | 不要把正文引用的其他类别当主类别 |
| `signals` | 关键词命中的证据句（每词最多 3 句，截断 500 字） | 按 codebook 判定，否定表述优先 |

无法读取、0 字节、低于 `--min-chars`、表格/图片/音视频、格式不支持都会写入 `skipped_documents.csv`，并在 `reason` 列说明原因；做样本流程时逐类对账，不要只写“其余排除”。`--audit` 只保留 `valid` 文件，`--dedupe-plan` 再剔除计划移动/复制的副本。

## 证据片段规则

每个编码值旁边保存一句原文，字段名统一为 `<变量>_ev`。

```json
{
  "file": "example_interview_001.txt",
  "stage": 3,
  "stage_ev": "示例：受访者表示相关款项已经支付，并提供了凭证",
  "outcome_binary": 1,
  "outcome_binary_ev": "示例：访谈记录明确提到该事项已经完成"
}
```

上例为虚构占位文本，不对应任何真实资料；实际编码必须引用原文。

规则：

- 证据句必须来自**资料正文/访谈原文/结果字段**，不能来自研究者概括、他人转述或附件中的建议。
- 否定表述优先：出现“不支持”“不足以认定”“未发生”时，不能因为同句出现“支持”就记 1。
- 一句话同时包含多个事实时，拆分到对应变量，不要整句复制到所有字段。
- 找不到证据句：记 `NA` 或 `未记载`，不要记 0。0 表示“文本明确说没有”，不是“没找到”。
- 同一份资料由多段组成时，记录段落/页码/时间戳，便于回溯。

## 有序层级变量

以“处理阶段”为例：

| 值 | 标签 | 判断要点 |
|---:|---|---|
| 0 | 未识别处理事实 | 全文没有可核实的承诺、支付、实施、确认 |
| 1 | 仅请求或判令 | 只有请求、建议或决定责令，未见主体主动行为 |
| 2 | 承诺或协议 | 承诺书、协议、计划、意向 |
| 3 | 已支付或缴纳 | 已支付/缴纳相关款项，有凭证 |
| 4 | 实际实施 | 已实际履行相关行为 |
| 5 | 已确认或完成 | 有确认、完成或效果评估记录 |

编码规则：

- 按资料时点**可查证的最高阶段**编码。
- 支付与实施并存，按更高阶段；只有支付凭证，不能推定已实施。
- “责令履行”是要求，不是已履行；不能记 4/5。
- “承诺履行”但没有后续履行，记 2，不记 4。
- 同一事项有多个版本时，以最终版/最完整版为准，并在证据中注明版本。

## 二元变量的正负规则

以“是否出现某结果”为例：

- 正例：同一句/相邻分句把某事实与结果表述明确连接。
- 反例：只提到事实，没有连接结果；或结果只针对其他情节。
- 排除：他人建议、转述、附件中的方案，未被最终资料采纳。
- 否定：明确写“不予支持/不足以认定/不适用”。

二元变量必须有“0 的定义”，否则 0 会混入“没写”“写了但没连接”“写了否定”三种情况。

## 问卷/量表/结构化抽取

- 先做项目级变量字典：题号、题干、取值、反向题、缺失码。
- 多选/排序题拆成 0/1 或多列；量表总分先检查信度（α/ω）和维度。
- 开放式题项先主题编码，再转成计数/类别变量；不要直接把词频当主题。
- 表格数据的主键、单位、时间字段必须能回溯到原始文件或原始行。
- 合并多来源数据时，先定主键与去重规则，再合并；保留来源列。

## 信度检验

至少做一次：

1. 随机抽 10%–15% 资料（不少于 30 份，太少没有意义）。
2. 两名编码员独立编码，或同一人隔两周重编码。
3. 对核心变量计算 Cohen's κ；κ < 0.6 的变量回到 codebook 修规则。
4. 分歧逐条裁决，记录裁决理由；codebook 升版本。
5. 在论文方法部分报告：抽样比例、κ、分歧处理方式。

## LLM 辅助编码的边界

LLM 可以：

- 抽取全文、标题、年份、编号、关键字段。
- 找出候选证据句。
- 按明确规则做初筛。
- 发现规则冲突和边界案例。

LLM 不可以：

- 在没有证据句的情况下直接给最终编码。
- 代替人工做理论赋分。
- 把“模型觉得像”写成“资料认定”。
- 在未抽检的情况下全量生成最终数据。

推荐流程：LLM 初筛 → 人工抽检 10% → 修正规则 → LLM 全量 → 人工复核高风险样本 → 冻结。

每次改 codebook，记录：

```text
版本：v3
日期：YYYY-MM-DD
改动：stage=3 增加“已支付”情形
影响：影响若干资料；模型 1 的 N 不变，OR 方向一致
```

没有日志的修改，半年后无法解释数字为什么变了。
