## 在真实正向链路中继续补齐的细节

- **更新后可以重新复核**：键被替换或行被删除后，历史事件仍留账，但不能阻断当前已完整重读的新表；当前 review 文件只保留现存目标，不沿用旧签名。
- **新争议阻断旧批准**：最新第二遍存在差异时，旧 verified 行不能让 final 通过；工作台与核验器统一按真实时间排序，混用 UTC 与 `+08:00` 不会续签旧确认。对应回归为 `test_new_dispute_overrides_previous_approval_across_timezones`。
- **权重和多份拟合输入不会被忽略**：内置入口明确要求使用实际支持这些语义的适配器；不因“可扩展”就伪称内置已经处理。
- **统计结果和设计有实际消费端**：真实聚类协方差和 GEE 分组拟合有正例；独立 IRLS 未收敛不能产生通过；不同目标、尺度、分母或时间窗不直接比较。
- **原生结构保真**：多维数组独立核对轴、顺序和大于浮点安全整数范围的值；DOCX 脚注等部件可定位，CSV 按逻辑记录处理；压缩包同名成员保留独立身份且路径不逃逸。
- **结论需要语境复读**：机械方向、极值和数字检查之外，还绑定实际重读来源、定位、身份和评估；重拟合或换引用后不能续签。
- **表格也要溯源**：注册表消费当前整表 final，其他结果表逐数值格给 trace；拒绝不规则行，核对实际打印单元格、图注和表题，避免正文通过但夹带假表。
- **PDF 保留原图**：导出使用临时文件并原子替换；回填前核对当前 DOCX 中的原图身份、唯一图注和实际 PDF 安置尺寸。错误图源拒绝回填，旧完整 PDF 保持可读。
- **位图字号有可核证据**：只有当前 live-artist 全文字记录、交付 PNG 像素复现和实际 DOCX/PDF 匹配安置都成立时才换算字号；仅有源矢量 PDF 或手填字号仍不通过。
- **成稿排版实看后修正**：章节标题跟正文跨页，表头续页重复，图与图注相连，去掉 Word Title 样式继承的蓝色边框；配色仍为推荐。

2. 原生格式和模型通过适配器开放扩展，不等于已解析所有二进制或已验证全部计算引擎。缺引擎、资料不足、失败、超时、不适用和未核明确保留，不能包装成正式推断。
3. 规模实测为 200k 行分块和 50k 行核对，另有长文本尾部、多个数据集/模型及并发故障测试。核验器仍有整表内存路径；更大规模和分布式场景没有被本次测试证明。执行记录中的内存峰值是当前 Python 进程累计峰值，未冒充单个测试或外部引擎的独立峰值。
4. A60 的旧批次先后顺序无法事后重建。现在的工具会拒绝缺执行证据或错误映射，但这不证明旧实现当时做过这些步骤。原“60 项全部通过”和“八批全通过”的历史声明已撤回，原文件保留于 `historical-implementation/`。
5. 当前只更新仓库源码、文档和 `.skill` 安装包，没有覆盖用户机器上已安装的其他副本，也未修改第三方插件。
